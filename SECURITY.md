# Модель безопасности PersonGuard

## Формат PGD2

`.pgd` — бинарный контейнер. Открытым остаётся только минимальный заголовок с версией, идентификаторами алгоритмов, параметрами Argon2id, солью и nonce. Название сейфа, сайты, URL, username/email, телефоны, пароли, избранное и даты находятся внутри аутентифицированного шифротекста.

1. Для каждого сейфа создаётся случайный 256-битный ключ данных.
2. Из мастер-пароля и случайной 128-битной соли Argon2id выводит ключ шифрования ключа: 128 MiB памяти, 4 прохода, параллелизм 2.
3. Ключ данных оборачивается AES-256-GCM с отдельным 96-битным nonce.
4. Содержимое сейфа шифруется тем же стандартом с новым случайным nonce при каждом сохранении.
5. Заголовок и обёрнутый ключ передаются как дополнительные аутентифицируемые данные. Любое изменение параметров, ключа, метаданных или содержимого приводит к отказу открытия.
6. При смене мастер-пароля генерируются новая соль и nonce и переоборачивается только случайный ключ данных. Сам мастер-пароль нигде не сохраняется.

Запись выполняется через временный **уже зашифрованный** файл с принудительной записью на диск и последующей заменой целевого файла. Размер импортируемого контейнера и параметры KDF ограничены до выделения ресурсов.

## Защита открытого приложения

- Пароль записи хранится в памяти в виде DPAPI-блока, связанного с текущим пользователем Windows и случайной энтропией конкретного процесса. Открытый массив байтов создаётся только на время шифрования, показа или копирования и затем обнуляется.
- Поля мастер-пароля и пароля приложения используют `SecureString`; временные UTF-8 буферы обнуляются.
- Локальный пароль приложения проверяется через Argon2id. Его соль, хеш и настройки хранятся в отдельном DPAPI-контейнере текущего пользователя Windows.
- Windows Hello можно включить только после настройки резервного пароля приложения. Оно используется при входе и для чувствительных действий.
- По умолчанию приложение повторно запрашивает Windows Hello или мастер-пароль перед показом пароля. Показ автоматически закрывается через 7 секунд.
- Копирование выключено по умолчанию. После явного включения запись помечается для Windows как исключённая из истории, облачной синхронизации и обработки мониторами буфера, а затем очищается через 20 секунд, если содержимое не было заменено другой программой.
- При блокировке сейф, защищённые секреты, граф и ссылки интерфейса очищаются; запускается принудительная очистка управляемой памяти.
- Загрузка DLL ограничена системными и явно разрешёнными каталогами; исполняемые образы из сети и low-integrity областей блокируются, а устаревшие точки внедрения отключаются. Приложение работает без прав администратора и допускает только один экземпляр.

## Граница защиты

PersonGuard надёжно защищает закрытый файл и обнаруживает его подмену, но ни одно desktop-приложение не может гарантированно победить вредоносный код, уже работающий с правами пользователя, администратора или ядра. Такое ПО способно перехватывать клавиатуру, читать память процесса, подменять исполняемый файл или фотографировать экран внешней камерой.

Защита окна уменьшает риск обычных снимков/трансляции экрана, но не является DRM и зависит от Windows. `SecureString`, DPAPI, короткое время показа и обнуление буферов сокращают поверхность атаки, но не делают секрет невидимым для отладчика или скомпрометированной ОС.

Рекомендуется:

- обновлять Windows и антивирус, включить Secure Boot, BitLocker и защиту от изменений Microsoft Defender;
- использовать стандартную учётную запись без постоянных прав администратора;
- задавать уникальный мастер-пароль длиной не менее 14 символов;
- держать приложение заблокированным, когда оно не используется;
- не включать буфер обмена без необходимости и отключить историю/облачную синхронизацию буфера Windows;
- хранить резервную копию `.pgd` отдельно и периодически проверять её открытие;
- использовать только сборки с ожидаемым SHA-256 и, для распространения, с доверенной Authenticode-подписью.

## Подпись релиза

Текущая локальная сборка помечается в интерфейсе как `DEV-сборка без подписи`, если сертификат отсутствует. Нельзя честно создать доверенную издательскую подпись без закрытого ключа владельца сертификата.

Скрипт `build-desktop.ps1` поддерживает реальную подпись: укажите отпечаток сертификата подписи кода из хранилища текущего пользователя в переменной `PERSONGUARD_SIGNING_THUMBPRINT`. Сборка завершится ошибкой, если подпись не получила статус `Valid`.
